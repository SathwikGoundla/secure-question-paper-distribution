# Backend — Setup & Run

FastAPI backend for the BLOCKCHAIN-ENABLED SECURE QUESTION PAPER DISTRIBUTION FRAMEWORK WITH TIME-LOCKED ACCESS project. This covers only the Phase 1 foundation —
see `docs/PHASE1_IMPLEMENTATION_STATUS.md` for what is and isn't implemented yet.

## 1. Prerequisites

- Python 3.11+ (developed/tested on 3.12)
- A running PostgreSQL server (13+)

## 2. Install dependencies

```bash
cd backend
pip install -r requirements.txt
```

> **Known issue, already fixed in requirements.txt:** `passlib==1.7.4` (the latest
> release of passlib, unmaintained since 2020) breaks at runtime with `bcrypt>=4.1`
> because passlib reads an attribute (`bcrypt.__about__.__version__`) that newer
> bcrypt releases removed. `requirements.txt` pins `bcrypt==4.0.1` to avoid this —
> installing exactly as listed avoids the issue. Do not upgrade `bcrypt` alone
> without also addressing this.

## 3. Configure environment variables

```bash
cp .env.example .env
```

Then edit `.env` and set at minimum:
- `DATABASE_URL` — your PostgreSQL connection string
- `JWT_SECRET_KEY` — generate one with:
  `python -c "import secrets; print(secrets.token_urlsafe(64))"`

**Never commit `.env`.** It's already listed in `.gitignore`.

## 4. Create the database

Using `psql` (adjust user/db names to match your `.env`):

```sql
CREATE USER qpaper_user WITH PASSWORD 'your-local-password';
CREATE DATABASE qpaper_db OWNER qpaper_user;
```

Then create the tables (Phase 1 uses a direct SQLAlchemy `create_all`, not a
migration tool — see "Known Limitations" in `docs/PHASE1_IMPLEMENTATION_STATUS.md`):

```bash
cd backend
python -m scripts.init_db
```

Expected output: a log line listing all 10 tables created (`roles`, `exam_centres`,
`users`, `papers`, `paper_authorizations`, `audit_events`, `security_events`,
`otp_codes`, `auth_sessions`, `exam_security_events`).

## 5. Run the backend

```bash
cd backend
uvicorn app.main:app --reload
```

The API is now available at `http://127.0.0.1:8000`.

## 6. Test the health endpoint

```bash
curl http://127.0.0.1:8000/api/v1/health
```

Expected response when everything is working:

```json
{"status": "ok", "app": "...", "environment": "development", "database": "connected"}
```

If PostgreSQL is unreachable, `status`/`database` will report `"degraded"` /
`"unavailable"` instead of the app crashing — this was verified during Phase 1
testing (see status doc).

Interactive API docs (Swagger UI, auto-generated by FastAPI): `http://127.0.0.1:8000/docs`

## 7. What's actually callable right now

**Fully implemented (Phase 2):** `POST /api/v1/auth/login`, `POST /api/v1/auth/otp/verify`,
`POST /api/v1/auth/logout`, `GET /api/v1/auth/me` — real password+OTP+JWT authentication,
backed by the real database.

**RBAC-protected but still scaffolded (Phase 3+):** `/api/v1/papers/*`, `/api/v1/admin/*`,
`/api/v1/exam-session/*`, `/api/v1/audit/*` — these now correctly enforce authentication
and role checks (401/403), but the underlying business logic still returns `501 Not Implemented`.

## 8. Provisioning test users (Phase 2)

There is no public "register" API — see `docs/PHASE2_IMPLEMENTATION_STATUS.md` for why.
Use the CLI:

```bash
python -m scripts.create_user --username admin1 --password 'Str0ng!Pass' --role Admin
python -m scripts.create_user --username centre1 --password 'Str0ng!Pass' \
    --role "Examination Centre" --centre-id <uuid-of-an-exam_centres-row>
```

## 9. Running the Phase 2 test suite

Requires the server running in one terminal (`uvicorn app.main:app`) and, in another:

```bash
cd backend
PYTHONPATH=. python tests/test_phase2_manual.py
```

This exercises all 18 required Phase 2 test cases against the real running server and
real database — see `docs/PHASE2_IMPLEMENTATION_STATUS.md` for full results.
